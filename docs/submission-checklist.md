## Demo, links, media and rights

- [ ] Keep the video at or below 30 seconds, or the entire deck at or below seven slides. Both are not required. Exceeding the limits makes a project ineligible for Global Judging.
- [ ] Use English in the project form and linked materials. A demo video may use other-language speech only with English subtitles; a deck is English.
- [ ] Host video/documents externally and link them; the form does not upload video/documents. Image uploads support JPG/PNG/GIF up to 10 MB.
- [ ] Test final project, demo and referenced files without login, password or permission in a private browser.
- [ ] Exclude under-18 persons' recognizable names, voices, photos/video/likenesses from submission content as described by the Terms. A screen-only demo with English text avoids filming team members; use a fictional commander name.
- [ ] Disclose SI use in the form and the project. Generated images/video need a visible generation watermark; audio needs descriptive attribution and metadata; code/data need descriptive attribution and metadata. SI-generated content must not use/contain/modify NASA branding/design elements.
- [ ] Review the team's idea-origin and rights statements honestly. SI assistance does not itself certify originality, and the assistant is not a registered team member.
- [ ] Review the selected [Apache-2.0 license scope](../LICENSING.md) and verify permissions/third-party license documentation before accepting the rights declaration. The user authorized this selection on November 15; adding a license does not certify every source right.

GitHub Pages, a particular disclosure filename, a PDF report, a project ZIP, child-playtest results and a bug-free completed product are not separately mandated documents in the reviewed guide. A direct game URL, clear README and automated tests are useful presentation/quality measures. Website filter classification is an optional recommendation in the guide, not a submission requirement.

## Actual submission

1. Open the profile menu, the team page and its Project tab; choose Edit. Coordinate one editor and use the editing lock.
2. Complete the fields and save progress frequently. **Save Progress is not submission for judging.**
3. Review the English content, links, sources and SI explanation. Accept the Terms and original-work/resource-rights declarations only when accurate.
4. Click **Submit for Judging before 23:59**. Confirm the success banner/message. Save confirmation evidence for the team.
5. If changed before the deadline, resubmit and verify success again. The guide says the last saved submission is the one reviewed.
6. Check the publicly displayed project page as a visitor. Retain the submitted version and source references; do not imply that a GitHub push itself submitted the project.

The actual Project form, demo, account/registration details, license choice and final confirmation remain team responsibilities. No assistant-generated checklist can guarantee eligibility or a particular judging outcome.
